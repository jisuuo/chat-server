## 내린 결정 (상세는 [`../adr/2026-10-07.md`](../adr/2026-10-07.md))

- ADR-040: 두 DB 컨테이너 각각 CPU 2개, 메모리 1GB, 캐시 메모리 256M(25%)
- ADR-041: 스키마 A/B를 바꿀 때는 DB를 비우고 다시 시작 (스키마별 데이터 분리는 채택 안 함)
- ADR-042: 마이그레이션 테스트는 테이블 존재만 확인 (제약은 F16과 작업 5 계약 테스트에서 드러남)
- ADR-043: 결정 기록을 날짜별 파일로 나눠 `docs/adr/`에 모음
- ADR-044: 에러 코드에 `NOT_FOUND`(404)·`METHOD_NOT_ALLOWED`(405) 추가, 나머지 Spring 요청 오류는 400, 문구는 코드마다 고정
- ADR-045: 입력 오류는 컨트롤러(DTO 검증)가 먼저 막고 도메인 검사는 안전망 (도메인은 `ChatException`을 못 던짐)
- ADR-046 ~ ADR-050: 인증 헤더 형식, 우회 회귀 검사, 코드 포인트 길이, 공백 이름과 제어 문자 규칙
- ADR-051: 방 목록을 넘기는 중 순서가 바뀐 방의 누락은 먼저 장애로 재현하기로 함

|---|---|---|

## 배운 점

- 오늘 작업에 나온 꼭 알아야 할 CS 지식 목록: [`../cs/2026-10-07.md`](../cs/2026-10-07.md)
- 실제로 확인한 DB 차이: MySQL은 FK 컬럼에 인덱스를 자동으로 만들고(`room_members.user_id`), PostgreSQL은 만들지 않는다. 기본 격리 수준은 MySQL REPEATABLE-READ, PostgreSQL read committed.
- 같은 스키마라도 "두 테이블이 공유하는 값"이 있으면 실험 조건을 바꿀 때 데이터가 섞인다.
